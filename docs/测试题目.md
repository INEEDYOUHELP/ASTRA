# Astra 平台代币经济模型全栈开发需求文档

## 1. 项目背景与目标 (Project Context and Goal)

### 1.1 项目概述

假设我们正在创建一个名为「Astra」的去中心化内容创作与策展平台。创作者可以在平台上发布文章、艺术品等内容，而用户（策展人）可以通过质押平台的原生代币「Astra Token」(ASTRA) 来支持他们喜欢的创作者，并从中获得收益。

你的任务是设计并实现这个经济模型的核心智能合约部分，并思考其与链下服务及前端应用的交互。

### 1.2 核心机制

用户通过质押 ASTRA 代币来支持创作者，并从策展行为中获得 ASTRA 代币奖励。

### 1.3 技术栈要求

- **目标网络**: 以太坊生态测试网（例如：Base Sepolia, Optimism Goerli 等）。
- **开发语言**: Solidity（智能合约）、JavaScript/TypeScript（部署脚本及前端交互）。

## 2. ASTRA 代币规格与分配 (ASTRA Token Specification)

### 2.1 ASTRA 代币合约 (ERC20)


| 规格项  | 要求描述                           |
| ---- | ------------------------------ |
| 代币名称 | Astra Token                    |
| 代币符号 | ASTRA                          |
| 标准   | 必须实现完整的 ERC20 代币标准             |
| 总供应量 | 恒定为 1,000,000,000（10 亿）枚 ASTRA |
| 精度   | 采用 18 位小数 (decimals)           |


### 2.2 初始代币分配 (Token Allocation)

代币必须在合约部署时一次性铸造（Mint）并分配至以下指定地址。


| 分配对象   | 占比  | 数量          | 目标地址类型                            |
| ------ | --- | ----------- | --------------------------------- |
| 生态系统基金 | 40% | 400,000,000 | 外部多签钱包（或具备多签权限控制的合约）              |
| 社区奖励池  | 30% | 300,000,000 | 质押与奖励合约 (Staking/Reward Contract) |
| 团队筹备   | 15% | 150,000,000 | 锁仓/归属合约 (Vesting Contract)        |
| 投资者奖励  | 10% | 100,000,000 | 锁仓/归属合约 (Vesting Contract)        |
| 流动性拨备  | 5%  | 50,000,000  | 部署者地址（用于后续 LP 注入）                 |


### 2.3 权限控制要求

所有分配部分的资金（生态系统基金、流动性拨备）都必须通过独立的角色或权限模型进行控制，**禁止使用单一的中心化管理员权限**。

## 3. 核心智能合约功能要求 (Core Smart Contract Requirements)

### 3.1 锁仓/归属合约 (Vesting Contract)

**目的**: 确保团队和投资者代币按预定时间表线性释放。

**功能规范**:

1. **多受益人支持**: 必须支持为不同的受益人（团队、投资者）设置独立的归属计划。
2. **提取功能**: 受益人可以随时提取当前已完全释放的 ASTRA 代币。

**归属计划参数与规则**:


| 受益人类型 | 总锁仓量              | 悬崖期 (Cliff) | 线性释放期 (Vesting) | 起始时间点           |
| ----- | ----------------- | ----------- | --------------- | --------------- |
| 团队筹备  | 150,000,000 ASTRA | 6 个月        | 24 个月           | ASTRA 合约部署完成的时刻 |
| 投资者奖励 | 100,000,000 ASTRA | 无 (0 个月)    | 18 个月           | 代币转账进入锁仓合约的时刻   |


### 3.2 质押与奖励合约 (Staking and Reward Contract)

**目的**: 管理社区奖励池，并根据用户质押的 ASTRA 数量和时间发放奖励。

**功能规范**:

1. **质押/赎回**: 用户可以随时质押 ASTRA，并随时赎回质押的本金。
2. **奖励来源**: 奖励资金来源于初始分配的「社区奖励池」(300,000,000 ASTRA)。
3. **奖励计算模型**:
  - 采用**简化的 APR 模型**：系统应设定一个固定的 ASTRA 数量，作为每秒钟释放的总奖励额度。
  - 奖励按比例分配给所有活跃质押者，即：`用户的奖励份额 = (用户质押量 / 总质押量) * 每秒释放量`。
4. **奖励领取**: 用户可以随时领取已赚取的奖励，领取行为不影响本金质押状态。

**安全与限制要求**:

- **资金安全阈值**: 合约必须持续监控其 ASTRA 代币余额。
- **锁定机制**: 当合约中的 ASTRA 余额低于社区奖励池初始总量的 1%（即 3,000,000 ASTRA）时，必须立即触发锁定机制：
  - 停止所有新的奖励发放。
  - 允许所有用户安全提取其剩余本金和所有已赚取奖励。

### 3.3 平台分佣合约 (Referral Commission Contract)

**目的**: 激励用户邀请新人加入并质押代币。

**功能规范**:

1. **推荐绑定**: 新用户在首次质押时，可以指定一个推荐人地址。
2. **奖励计算**: 推荐人获得被推荐人当前首次质押量的 **5%** 作为一次性奖励。
3. **奖励来源**: 奖励从社区奖励池中扣除。
4. **奖励领取**: 推荐人必须手动领取此推荐奖励。

## 4. 部署与集成要求 (Deployment and Integration Requirements)

### 4.1 Uniswap 流动性接入 (Deployment Script)

要求：必须编写一个部署脚本，在所有智能合约部署完成后，自动执行以下操作：

1. **资金转移**: 从 ASTRA 合约分配的「流动性拨备」中取出部分 ASTRA 代币，并准备一定数量的 ETH。
2. **LP 创建**: 与 Uniswap V2（或 V3）的 Router 合约交互，以创建 ASTRA/ETH 交易对的初始流动性池 (LP)。
3. **LP 代币处理**: 将创建流动性后获得的 LP 代币发送回合约所有者地址。

### 4.2 预言机与动态平衡机制 (Oracle and Dynamic Burn Mechanism)

**场景扩展**: Astra 平台将引入链下交易订单数据（数据内容可自拟）。

**功能要求**:

1. **数据喂价**: 实现一个机制（或模拟预言机）来监控链下数据。
2. **动态检查**: 预言机必须能够动态地检查项目方在某个预设时间段内是否有新的资金充入 Uniswap 流动性池。
3. **平衡机制**: 根据 Uniswap LP 池中 ASTRA/ETH 的币值动态，如果项目方在特定时间窗内未充入资金，则触发销毁一定量的 ASTRA 代币作为经济平衡。
  - **要求**: 开发者需要自拟用于触发销毁的具体条件和销毁数量。
